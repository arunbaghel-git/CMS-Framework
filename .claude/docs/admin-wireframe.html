What v2 added here

  1. 1Staging warning banner. Driven by settings.searchEngineVisible. A client staging site getting indexed by Google is the most expensive routine accident an agency has — so the reminder is permanent, not a settings checkbox nobody revisits.
  2. 2Pending review count. The pending status was missing, which left the contributor role with no way to say "I'm done." Editors need this number on the dashboard, not buried in a filter.
  3. 3Trash count. Soft delete via deletedAt, reserved day one because it touches every list query and index.
  4. 4Site health strip. Core version, pending migrations and last backup — the fleet questions you need answered per client without SSHing in.

What v2 added here

  1. 1Status count tabs, including Trash and Private. Five statuses instead of three. private covers client staging pages that are live but login-only.
  2. 2Row actions on hover — Edit · View · Duplicate · Trash. View is the one people use constantly and it was missing entirely. The "front page" marker comes from settings.homepageEntryId.
  3. 3A real URL column, from the stored path field. Nested pages resolve through parentId; renaming a parent cascades to every descendant and writes a 301 for each.
  4. 4Bulk actions. A client with 200 posts and no bulk operations calls you instead of doing it themselves.

What v2 added here

  1. 1Autosave recovery. The plan had 30-second autosave but no way to get the autosave back. This is the payoff for having it at all.
  2. 2Revisions on save, not only on publish — 14 here, not 2. The real recovery case is "I saved and broke it." Browsing shows a changed-summary, because restoring blind from a timestamp list is frightening for a non-technical user.
  3. 3SEO title templates. The fallback chain had no pattern layer — entry SEO, then %title% | %sitename%, then defaults, then title/excerpt.

What v2 added here

  1. 1Floating block toolbar. Align, link, duplicate, delete, move. Sending every high-frequency action to the right-hand panel makes editing feel slow — the panel is for configuration, the toolbar is for editing.
  2. 2Document / Block tabs. In builder mode there was previously nowhere to set slug, status, template or categories. This is the gap that closes it.
  3. 3Responsive inherit indicator. Backed by the real decision underneath: style.{desktop,tablet,mobile} compiles to server-generated scoped CSS with actual media queries — inline styles cannot express them at all.
  4. 4Sandboxed canvas iframe. Untrusted block content executing same-origin with an admin session is the highest-value target in the system.

What v2 added here

  1. 1Media trash. Same deletedAt treatment as entries.
  2. 2Crop / rotate and Replace file. A non-technical user has no other image tool. Replace swaps the file while the URL and every reference stay intact.
  3. 3"Used in 3 places", from the mediaRefs backlink index. The plan promised delete-with-usage-check but had no structure that could answer it — image references sit buried inside arbitrary-depth block trees.

What v2 added here

  1. 1Menus and locations are separate. The fixed key(main|footer) meant a client wanting a second footer menu needed a code change — which breaks the framework's own "no code per client" premise. Build any number of menus; the theme declares the locations.
  2. 2Per-item target and CSS class. A "Book Now" nav button is a menu item with a class, and agencies ask for one on nearly every build.

What v2 added here

  1. 1Front page configuration. Three planning documents never said how / resolves. This screen is the answer, and the posts page setting is what makes /blog exist as a URL with working pagination.
  2. 2Search engine visibility. One toggle, site-wide noindex plus robots.txt, with the admin banner that keeps it from being forgotten.
  3. 3Permalinks per content type. Deliberately a small, sane set — no ?p=123, numeric or date-based patterns. Changing one after publishing generates redirects rather than silently breaking URLs.
